# myproject performance

This page is **yours**. `benchbook` reads it, links it in the navigation and never
rewrites it — the generated pages live next to it and start with
`<!-- generated by benchbook: DO NOT EDIT -->`.

## How this documentation works

Every claim on the generated pages comes from a recorded run:

- **Benchmarks** — the current working run and, for each milestone, what changed and
  whether the change survived the statistics.
- **Profiling** — the `pprof -top` tables captured with `benchbook profile`, quoted
  verbatim so you can check the numbers against the tool that produced them.
- **Timeline** — the milestone chain, one point per milestone, with a break drawn
  wherever the hardware changed.
- **Compare** — pick any two runs; the page runs the same Mann-Whitney U test the CLI
  does, in your browser, from the exported JSON.

## What to write here

Use this page for the things a measurement cannot say: which workloads you care
about, what the machine looks like, what "fast enough" means for this project, and
which regressions are acceptable and why. Keep the numbers on the generated pages and
the intent here — the two together are the documentation.

## Running it

```console
$ benchbook run                      # record the working run
$ benchbook status                   # what changed since the last milestone
$ benchbook milestone -m "what I did"  # promote it into the history
$ benchbook build && benchbook serve   # read the site locally
```
